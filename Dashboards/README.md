# Dashboards

Dashboards are presentation only. Every number they show is read from the governed marts in `metrics.*` / `core.*`; no KPI is calculated in a BI tool.

## 1. Web dashboard (included)

`index.html` + `dashboard_data.js`: KPI strip, revenue and order trend, on-time rate against the 85% floor, review score by lateness, carrier transit vs seller handling, top categories, seller tiers, and a sortable state table.

- Open `index.html` in a browser (it loads Chart.js from a CDN, so it needs an internet connection), or
- Turn on GitHub Pages (Settings → Pages → deploy from `main`, root folder) and open `/Dashboards/`.

`dashboard_data.js` is regenerated by `python analysis/run_analysis.py`.

## 2. Power BI report (build guide)

The `.pbix` is built from the governed marts. Save it here as `Dashboards/DecisionGrade.pbix` and add page screenshots to `Dashboards/screenshots/`.

### Connect

Option A, CSV (simplest): **Get Data → Text/CSV** on the files in `Data/processed/` for the KPI tables. For the star schema, export the core tables first:

```bash
python - <<'PY'
import duckdb
con = duckdb.connect("warehouse/decisiongrade.duckdb", read_only=True)
for t in ["fact_order_finance", "fact_order_items", "fact_delivery_performance",
          "dim_customer", "dim_product", "dim_seller", "dim_location", "dim_date"]:
    con.execute(f"copy core.{t} to 'Data/processed/{t}.csv' (header)")
PY
```

Option B, cloud warehouse: after `dbt build --target cloud`, connect Power BI to MotherDuck with its ODBC/DuckDB connector.

### Model view

Create single-direction, many-to-one relationships:

| From (many) | To (one) |
|---|---|
| `fact_order_finance[customer_key]` | `dim_customer[customer_key]` |
| `fact_order_finance[purchase_date_key]` | `dim_date[date_key]` |
| `fact_order_finance[location_key]` | `dim_location[location_key]` |
| `fact_order_items[product_key]` | `dim_product[product_key]` |
| `fact_order_items[seller_key]` | `dim_seller[seller_key]` |
| `fact_order_items[purchase_date_key]` | `dim_date[date_key]` |
| `fact_delivery_performance[purchase_date_key]` | `dim_date[date_key]` |
| `fact_delivery_performance[customer_location_key]` | `dim_location[location_key]` |
| `fact_delivery_performance[seller_key]` | `dim_seller[seller_key]` |

Mark `dim_date` as the date table (`date_day`).

### Measures (thin wrappers over warehouse columns, no new logic)

```DAX
Net Revenue = SUM ( fact_order_finance[net_revenue] )
Orders Delivered = CALCULATE ( COUNTROWS ( fact_order_finance ), fact_order_finance[is_revenue_recognized] = TRUE () )
Average Order Value = DIVIDE ( [Net Revenue], [Orders Delivered] )
On-Time Rate = AVERAGEX ( fact_delivery_performance, IF ( fact_delivery_performance[is_on_time], 1, 0 ) )
Avg Days To Deliver = AVERAGE ( fact_delivery_performance[cycle_time_days] )
Avg Review = AVERAGE ( fact_delivery_performance[review_score] )
Repeat Customer Rate = AVERAGEX ( dim_customer, IF ( dim_customer[is_repeat_customer], 1, 0 ) )
```

Check after building: Net Revenue = R$13,221,498.11 and On-Time Rate = 93.2% for the full period. If the report shows different numbers, a filter or relationship is wrong; the warehouse is the reference.

### Suggested pages

1. **Executive**: KPI cards, monthly Net Revenue (column), On-Time Rate (line) with an 85% constant line.
2. **Delivery**: filled map or bar of On-Time Rate by `dim_location[state_code]`; Avg Days To Deliver by region; review score by `lateness_band`.
3. **Sellers & categories**: `seller_scorecard` table with conditional formatting on `seller_tier`; top categories by revenue.
